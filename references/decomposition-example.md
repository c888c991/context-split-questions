# 拆解示例

这是第 1 步"拆子问题"的完整示例。只展示拆法，照抄结构，不要照抄内容。

## 原始问题

```text
请根据这 300 页项目资料，分析项目 A 为什么延期、谁负责、合同风险是什么、如何补救、对后续排期有什么影响。
```

这个问题同时含五个需要各自取证的维度（原因、责任、风险、补救、影响），材料又远超上下文，所以要先拆。

## 拆出的子问题

- **Q1 延期事实**：项目实际时间线和原计划差多少？
  - 需要信息：计划里程碑、实际完成日期、变更记录
  - 输出格式：时间线
  - 依赖：无
- **Q2 直接原因**：哪些事件直接导致延期？
  - 需要信息：周会记录、邮件、变更单
  - 输出格式：列表，每条带证据编号
  - 依赖：无
- **Q3 责任方**：各原因分别对应哪个团队 / 供应商 / 决策？
  - 需要信息：Q1 的时间线、Q2 的原因清单、合同与审批记录
  - 输出格式：表格（原因 / 责任方 / 依据）
  - 依赖：Q1、Q2
- **Q4 合同风险**：延期触发了哪些违约、赔偿、终止条款？
  - 需要信息：合同条款原文、延期天数
  - 输出格式：列表，引用条款编号与原句
  - 依赖：Q1
- **Q5 补救方案**：资料中提到了哪些补救措施？
  - 需要信息：会议记录、补救方案文档
  - 输出格式：列表
  - 依赖：无
- **Q6 后续影响**：对后续里程碑和资源排期有什么影响？
  - 需要信息：Q1、Q5、排期表
  - 输出格式：表格或时间线
  - 依赖：Q1、Q5

## 落盘与状态

清单先写进 `work/answers/proj-a-delay/00-子问题清单.md`（任务目录名用 ASCII 与连字符）交给用户确认；之后每块摘要写进 `chunks/`，每个子答案写进 `answers/`，最后汇总写 `汇总报告.md`。新会话接手只读清单和相关 `chunks/`。

材料如果不在磁盘上（粘在对话里的记录、截图、扫描件），先原样落盘到 `source/` 再切块。

## 会话策略判断

- Q2 与 Q5 互相独立（一个查原因、一个查补救），彼此不需要结论，可以提醒用户换会话并行做。
- Q3、Q4、Q6 需要 Q1 的结论，留在同一会话按顺序做。
- 拿不准时默认同会话，避免重新探索材料。
- 上下文偏紧时，先写阶段报告落盘，再提醒用户 `/compact`。

## 拆解的判断标准

拆得对不对，看三条：

- 可独立回答：不依赖别的子问题的原文也能答出东西；
- 可验证：有明确的证据来源可以核对；
- 有明确输出：能说清交付物是列表、表格、时间线还是结论。

三条缺一条，说明拆得太粗或太碎，重新拆。如果拆的过程中发现材料其实能一次读完、或子问题没法独立回答，就停止拆分、退回普通做法，不要硬拆。
